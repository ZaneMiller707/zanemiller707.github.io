Get post data from JSONPlaceholder in 10 minutes

A beginner REST API tutorial: one curl request, what the response means, and what to do when it breaks.

Before you start

You need a terminal with curl installed. Mac and Linux have it built in; on Windows, it ships with Windows 10 and later. No API key or account is required — JSONPlaceholder is a free test API that returns fake data, made for exactly this kind of practice.

Your first request

Open your terminal and run this command:

curl https://jsonplaceholder.typicode.com/posts/1

Here's what each part of the URL means:

  • https:// — the protocol. APIs are almost always called over HTTPS.
  • jsonplaceholder.typicode.com — the server you're asking.
  • /posts/1 — the resource: "give me post number 1." Changing 1 to another number (1–100) returns a different post.

Reading the response

The server answers with JSON — a text format that lists keys and values. You should see something like this:

{
  "userId": 1,
  "id": 1,
  "title": "sunt aut facere repellat provident occaecati excepturi optio reprehenderit",
  "body": "quia et suscipit\nsuscipit recusandae consequuntur expedita et cum..."
}

Each key tells you something about the post:

  • id — the post's unique number. This is the 1 you put in the URL.
  • userId — the author of the post.
  • title and body — the post's content. The \n characters are line breaks inside the text.

The most important takeaway: the request URL describes what you want, and the JSON response is the answer. Almost every REST API works this way.

Try changing the request

Swap the ID for another number and see what comes back:

curl https://jsonplaceholder.typicode.com/posts/42

Now try an ID that doesn't exist, like 999:

curl https://jsonplaceholder.typicode.com/posts/999

You'll get an empty {} — the server understood the request, but there's no post 999. This is normal API behavior, not a bug in your command.

When it breaks

Most failures come down to three things: a typo in the URL, no internet connection, or asking for a resource that doesn't exist. If you get an empty response or curl can't reach the server, walk through the symptoms in the troubleshooting guide — each one is listed with its exact fix.
