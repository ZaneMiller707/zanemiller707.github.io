Fix Common JSONPlaceholder Request Errors

This guide covers the most frequent problems when calling the JSONPlaceholder test API, how to recognize each one, and how to fix it. Start with the symptom that matches what you see.

1. You got a 404 and expected data

What it looks like:

curl https://jsonplaceholder.typicode.com/posts/999
{}

An empty {} with no error message.

What's happening: You asked for a post ID that doesn't exist. JSONPlaceholder only has posts with IDs 1 through 100.

How to fix it: Use an ID between 1 and 100:

curl https://jsonplaceholder.typicode.com/posts/1

2. You expected one post but got an array

What it looks like: The response starts with [ and contains many posts instead of one.

What's happening: You called /posts (all posts) instead of /posts/{id} (one post). A missing or mistyped ID returns the full list.

How to fix it: Add the ID to the URL:

# Returns everything (probably not what you want):
curl https://jsonplaceholder.typicode.com/posts

# Returns one post:
curl https://jsonplaceholder.typicode.com/posts/1

3. curl can't reach the server

What it looks like:

curl: (6) Could not resolve host: jsonplaceholder.typicode.com

What's happening: Your computer can't find the server — usually a network connection problem or a typo in the URL.

How to fix it:

  1. Check your internet connection.
  2. Retype the URL carefully. The domain is jsonplaceholder.typicode.com — easy to misspell.
  3. Make sure you are using https://, not http://. Plain HTTP is redirected and can confuse some tools.

4. You see a 500 error

What it looks like:

HTTP/1.1 500 Internal Server Error

What's happening: Something went wrong on the server side. JSONPlaceholder is a free demo service and occasionally has outages.

How to fix it: Wait a minute and try the exact same request again. If it still fails after a few retries, check whether the service is down by opening the URL in your browser — if the browser fails too, the problem is not your code.

5. The response isn't valid JSON

What it looks like: Your parser throws an error, or you see HTML instead of JSON.

What's happening: The most common cause is a typo in the URL path (for example /post/1 instead of /posts/1), which routes to a page that returns HTML.

How to fix it: Compare your URL against the docs character by character. The resource paths are plural: /posts, /comments, /users.
